## Install this fork

For **edmundmiller/issue-graph**, follow [the fork README's Start here](https://github.com/edmundmiller/issue-graph#start-here): clone that repository, build with pinned pnpm, pack it, and install the resulting tarball into a dedicated user prefix. Node.js 24 LTS is recommended. `issue-graph@latest` is the upstream npm package, not this fork. Keep the fork executable on your PATH for all examples below.

Verify `issue-graph schema` lists `commands.open.workProviders.providers` with all four providers, then read `issue-graph skills get core --full`. The README includes a credentials-free Beads example and exact environment/scope configuration for live providers. GitHub alone requires `gh`. Importing tracked Beads JSONL requires neither credentials nor br/bd; native unclosed statuses do not imply readiness, and exports can lag database-backed changes.

## Prerequisites

- Node.js 20 or later
- [GitHub CLI](https://cli.github.com) on your `PATH` for GitHub collection only
- Authorized scope/credentials for the live provider you want to query; none for Beads JSONL

## Try a credentials-free snapshot

From the cloned checkout, import the bundled Beads fixture into an isolated local store:

```bash
ISSUE_GRAPH_HOME="$PWD/.fork-demo" issue-graph open beads:demo --input examples/beads/issues.jsonl --state all
ISSUE_GRAPH_HOME="$PWD/.fork-demo" issue-graph query beads:demo --view explore --json --no-open
```

The capture contains three records with native `blocked`, `in_progress`, and `open` statuses and two directed dependencies. The query returns the exact local `viewUrl`. This confirms fixture import and offline rendering, not live access or tracker readiness. See [Dashboard and saved queries](/docs/dashboard) for capabilities and storage.

Run `issue-graph --help` to see the commands supported by your installed release. If a command is missing, check that your PATH selects the fork and follow [Update](#update).

## Authenticate GitHub

```bash
gh auth login
issue-graph auth status
```

issue-graph uses your GitHub CLI credentials. `issue-graph auth status` reports sign-in state without printing tokens. For GitHub CLI diagnostics, run `gh auth status`. To query a private repository, your account needs access to it and any SSO authorization the organization requires.

## Trace an issue

Start with [agent-browser issue #1113](https://github.com/vercel-labs/agent-browser/issues/1113):

```bash
issue-graph graph vercel-labs/agent-browser#1113 --depth 1 --budget 12 --no-save
```

You can also pass the issue URL:

```bash
issue-graph graph https://github.com/vercel-labs/agent-browser/issues/1113 --depth 1 --budget 12 --no-save
```

The command prints a formatted report in a terminal and Markdown when piped. This example, captured on 2026-09-22, found a merged fix and two open follow-ups:

| Issue or PR | Captured state | Description |
| --- | --- | --- |
| [Issue #1113](https://github.com/vercel-labs/agent-browser/issues/1113) | CLOSED | Original orphaned Chrome report |
| [PR #1137](https://github.com/vercel-labs/agent-browser/pull/1137) | MERGED | Fix linked to #1113 |
| [Issue #1148](https://github.com/vercel-labs/agent-browser/issues/1148) | CLOSED | Regression after the fix |
| [Issue #1371](https://github.com/vercel-labs/agent-browser/issues/1371) | OPEN | Chrome Helper using high CPU |
| [Issue #1607](https://github.com/vercel-labs/agent-browser/issues/1607) | OPEN | GUI Chrome launch problem on macOS |

Each run queries GitHub, so your results may differ. The flags limit the crawl to depth 1 and 12 fetched nodes, and `--no-save` skips saving a new snapshot. Before you act on the report, check its missing references and limits. See [Graph](/docs/graph) for the capture details and crawl limits.

## Save an explorer

To save the results, add `-o` with a `.json` or `.html` path:

```bash
issue-graph graph vercel-labs/agent-browser#1113 --depth 1 --budget 12 --no-save -o graph.json -o graph.html
```

Open `graph.html` in your browser. If you move it, move its sibling `_next/` directory and `font-LICENSE.txt` with it. Export paths write files even with `--no-save` and replace existing files, so choose new filenames to keep earlier results.

To filter results from the CLI and get an exact dashboard link, save a model first:

```bash
issue-graph open vercel-labs/agent-browser --no-open
issue-graph query github:vercel-labs/agent-browser --state open --kind Issue --view rank --json --open
```

The first command collects data from GitHub within its crawl budget. The second reads the saved data offline, makes no GitHub requests, and returns a `viewUrl` for the matching dashboard view. See [Dashboard and saved queries](/docs/dashboard) for Heat, clusters, replay, and scoring defaults.

## Connect another provider

For native Linear graphs, authorize a read-only browser session, then capture an issue or a project:

```bash
issue-graph linear login
issue-graph linear ENG-123 --workspace your-workspace --open
issue-graph linear --project 12345678-1234-1234-1234-123456789abc --open
```

Replace the sample workspace, identifier, and project UUID with your own. Native Linear also accepts `LINEAR_API_KEY` or `LINEAR_ACCESS_TOKEN`; see [Linear](/docs/linear). The legacy `open linear:PROJECT_UUID` inventory still requires an environment token and does not use the login session.

For Jira, Notion, and Beads, use provider-qualified `open` commands. Read `issue-graph open jira:PROJECT --help` or the equivalent help for your scope, then follow the [fork README's provider setup](https://github.com/edmundmiller/issue-graph#work-providers-in-this-fork). Keep credentials in your authorized environment or secret manager, never in command arguments or chat.

## Update

From your clean fork checkout, follow [Update the fork installation](https://github.com/edmundmiller/issue-graph#update-the-fork-installation): pull the reviewed fork changes, install locked dependencies, pack the source, and reinstall that tarball into the dedicated prefix. Use the filename printed by `pack` when the version changes.

After updating, run `issue-graph schema` and verify `commands.open.workProviders.providers`. Updating from the npm registry would replace this fork with upstream.

## Troubleshooting

If your shell cannot find `issue-graph`, put `$HOME/.local/issue-graph-fork/bin` on your PATH or use the full executable path. Run `command -v issue-graph` to confirm that your shell selects the fork. For GitHub access errors, run `gh auth status` and check your repository permissions and SSO authorization. See [Troubleshooting](/docs/troubleshooting) for Linear authentication and partial captures.

## Optional source development

To build from source, use pnpm and Node.js 20.19.x or 22.12 and later. Node.js 24 is recommended.

```bash
git clone https://github.com/edmundmiller/issue-graph.git
cd issue-graph
npm exec --yes --package=pnpm@10.34.5 -- pnpm install --frozen-lockfile
npm exec --yes --package=pnpm@10.34.5 -- pnpm build
node dist/bin.js --help
```

Continue with [Graph](/docs/graph), [Status and history](/docs/status), or [Agents and skills](/docs/agents).
