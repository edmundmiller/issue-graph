`issue-graph` traces GitHub issues and pull requests, native Linear issue and project relationships, and this fork's read-only Jira, Notion, and Beads inventories. Use it to find existing fixes, check review status, and decide what to review next.

## Install this fork

For Jira, Linear, Notion, and Beads support, install **edmundmiller/issue-graph** from [the fork README](https://github.com/edmundmiller/issue-graph#start-here). Its source-pack installation and credentials-free Beads example select the fork explicitly. Check `schema` and read its bundled core guide; the upstream npm package and issue-graph.dev do not install this fork.

Use Node.js 20 or later at runtime; Node.js 24 LTS is recommended for the source build. GitHub collection also needs the [GitHub CLI](https://cli.github.com) and an authorized `gh auth login`. Native Linear can use a read-only browser login or environment credentials. Beads JSONL imports work without credentials.

## Trace an issue

```bash
issue-graph graph vercel-labs/agent-browser#1113 --depth 1 --budget 12 --no-save
```

The report lists the linked issues and PRs, their current states, and possible follow-ups. To trace your own work, pass an issue URL or replace the repository and number.

See [Get started](/docs/get-started) for a walkthrough and example output.

## Commands

| Task | Command | Guide |
| --- | --- | --- |
| Capture a backlog and open its dashboard | `issue-graph open owner/repo` | [Dashboard and saved queries](/docs/dashboard) |
| Trace linked issues and PRs | `issue-graph graph <issue-or-pr>` | [Graph](/docs/graph) |
| Rank a live backlog by Heat | `issue-graph rank owner/repo` | [Graph](/docs/graph) |
| Group related work with your agent | `issue-graph cluster owner/repo` | [Agents and skills](/docs/agents) |
| Filter saved work and open its exact view | `issue-graph query provider:scope --open` | [Dashboard and saved queries](/docs/dashboard) |
| Collect Jira, Notion, or Beads work | `issue-graph open provider:scope` | [Provider scope](/docs/dashboard#provider-and-project-scope) |
| Read Linear issue relationships | `issue-graph linear <issue>` | [Linear](/docs/linear) |
| Count PRs by author and review state | `issue-graph status` | [Status and history](/docs/status) |
| Find backlog items to verify | `issue-graph reconcile` | [Reconcile and plan](/docs/backlog) |
| Choose the next review or investigation | `issue-graph plan` | [Reconcile and plan](/docs/backlog) |

`config` sets scoring defaults, `dashboard` and `runs` manage saved models, and `auth status` reports sign-in state. The [Command reference](/docs/reference) lists every command and flag.

## Use with agents and applications

Install the [agent skill](/docs/agents) to run issue-graph from a coding agent. The [library](/docs/library) exposes the same collectors and renderers to your application code. Most commands can also print JSON for scripts and agents.

## Review results

The CLI reads provider data without changing it and reports gaps caused by access errors or collection limits. Native unclosed statuses do not establish readiness. Check those gaps and inspect the linked code before you close an issue or merge a PR.

Graph and reconcile save local history by default. See [Permissions and privacy](/docs/security) for storage controls and the [Command reference](/docs/reference) for flags and output formats.
